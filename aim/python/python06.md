## 问1：简要介绍 VS Code 中各种不同的 Python 交互方式

答：VS Code 里的 Python 交互方式，主要可以按“轻量到重型”来理解。它们核心的区别在于：**是否保留执行历史、功能丰富程度、以及是否依赖 Jupyter 内核**。

- Native REPL：带智能提示的轻量交互
这是 VS Code 对经典 REPL 的增强版。它最大的优点是**启动快、占用低**，同时额外提供了 IntelliSense（代码补全）和语法高亮。不过，它遵循原生 REPL 的规则：**历史执行顺序和内容是不可更改的**，你不能像 Notebook 那样回头重跑之前的某一行。适合快速验证语法、测试一小段逻辑。

- Terminal REPL：最传统的终端模式
这就是在 VS Code 集成终端里打开的 `>>>` 提示符，和你直接在系统命令行里敲 `python` 完全一样。功能最基础，没有智能提示，但胜在纯粹、稳定。如果你习惯在终端里操作，或者需要确保环境与外部终端完全一致，就选它。

- Jupyter Notebook：功能完整的分析画布
这是最“重”但也最强大的方式，会创建 `.ipynb` 文件。它的核心优势是**单元格可以按任意顺序反复执行**，并且支持 Markdown 说明、内嵌图表、变量查看器等。适合数据分析、探索性编程，或者需要记录步骤和结果的工作。它依赖 Jupyter 内核，资源占用相对更高。

- Python Interactive Window: 它本质上是一个以 `.py` 文件为输入源的 Notebook 式窗口，介于脚本和 Notebook 之间，适合在写脚本时进行分段交互调试。

简单总结：**图快选 Native REPL，求稳选 Terminal REPL，做分析或需要反复调整代码块就选 Jupyter Notebook。**

## 问2：什么是 Jupyter 内核？

答：Jupyter 内核本质上是一个**独立的、运行特定编程语言代码的进程**。它负责接收你（通过 Notebook 或交互窗口）发送的代码，执行它，然后把结果送回来。

1.  它是如何工作的？你可以把它想象成一个后台的“计算引擎”：
    - **前后端分离**：你在 VS Code 里看到的界面（前端）只负责显示和编辑。真正的代码执行发生在另一个独立的“内核”进程里。
    - **通信方式**：前端和内核之间通过特定的消息协议（基于 ZeroMQ 套接字）进行通信。
    - **状态保持**：只要内核没关闭，它就会一直保留你定义的变量和状态，所以你可以分多次运行代码块，后面的代码能用到前面的变量。

2.  Python 内核具体指什么？
    对于 Python，最常用的内核是 **`ipykernel`**。它建立在 IPython 之上，是 Jupyter 官方维护的参考实现。当你在 VS Code 里为 Jupyter Notebook 或 Interactive Window 选择 Python 环境时，实际上就是在指定用哪个 Python 解释器来启动这个 **`ipykernel`** 进程。

## 问3：是否可以在vscode里以网页方式打开html？

答：如果你使用的 VS Code 版本较新（1.121 及以上），它已经内置了预览 HTML 文件的功能。

操作非常简单，任选一种即可：
*   **右键文件**：在左侧文件资源管理器中，右键点击你的 `python05.html` 文件，选择 **“Open in Integrated Browser”**。
*   **右键标签页**：如果文件已经在编辑器里打开，右键点击该文件的标签页，选择同样的选项。
*   **点击图标**：当 HTML 文件处于激活状态时，点击编辑器右上角出现的 **“Preview”** 图标（通常是一个小眼睛或放大镜的样子）。

这样，网页就会直接在 VS Code 内部的一个新标签页里打开，你可以边看代码边看效果。

## 问4：如何在Native REPL 里输入多行Python代码？

答：在 Native REPL 里输入多行代码，最直接的方式是**利用编辑器的“智能发送”功能**，而不是在 REPL 的输入框里手动敲换行。

- 推荐方式：在 .py 文件里写好后“发送”。这是 VS Code 为 Native REPL 设计的标准用法，能避免手动处理缩进和换行的麻烦。

    1.  在普通 `.py` 文件中写好完整的多行代码（比如一个 `for` 循环或函数定义）。
    2.  按快捷键 `Ctrl+,`，打开 VS Code 设置，把 `"python.REPL.sendToNativeREPL"` 设为 `true`。
    3.  将光标放在代码块内，或者选中你想运行的部分。
    4.  按下 **`Shift + Enter`**。

  VS Code 的“智能发送”（Smart Send）会自动识别光标处“最小的可运行代码块”，并将其完整地发送到 Native REPL 执行。这样你就不需要在 REPL 的输入行里手动按回车来续行，也避免了缩进错乱的问题。

- 备选：直接在 REPL 输入框手动换行

  如果你坚持要在 REPL 输入框直接输入，Native REPL 本身是支持多行输入的，不像传统终端 REPL 那样容易和命令历史冲突。在输入像 `if` 或 `for` 这样的语句后，直接按回车，REPL 通常会自动进入缩进续行状态（提示符可能变为 `...`），等你输入完代码块后，再按一次回车执行。

  不过，手动输入时要注意：如果你是从别处**复制粘贴**多行代码进去，可能会因为编辑器自动插入的缩进和你粘贴文本自带的缩进叠加，导致缩进错误。所以对于稍复杂的代码块，还是推荐用第一种“在文件里写好后 `Shift+Enter` 发送”的方式，最省心。
